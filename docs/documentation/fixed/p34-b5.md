# Phase 34, lane b5: `volvel dev` for widgets

## What changed
- `packages/cli/src/dev-widgets.ts` (new): `startWidgetServer`. `/_dev/widgets` lists the repository's widgets; `/_dev/widgets/x/<name>` is the preview; `/_dev/widgets/data/<name>.json` is what the page reads (definition, config = schema defaults < `defaults` < fixture config, data = fixture.json or `sampleData()` made from the declared inputs, state, build problems); `/_widgets/dev/x/<name>@<version>/{frame.html,view-*.js}` serves the files `buildWidgets` makes (b2) under `WIDGET_POLICY`, no cookie. The preview page has its own policy (`PREVIEW_POLICY`: script 'self', frame-src 'self', connect 'self'). A watcher (150 ms) rebuilds and sends an SSE `reload`.
- `packages/screens/runtime/dev-widget-host.ts` (new): the page's script, no React. Same sandboxed iframe attributes, `createChannel` (frameChannel.ts), `readTheme`, props posting and `event.source` check as `TenantWidgetHost`; not changed. Controls: size (1440/768/390 presets, width, height), theme, state, config form drawn from the schema (text, select, number, boolean, JSON for others; `x-volvel.label` used, not the inspector's control drawing, which lives in the console), data JSON. Event log with passed/dropped and reason. Build errors in an alert. Config, size, theme kept over a rebuild and a reload (sessionStorage).
- `packages/cli/src/cli.ts`, `commands.ts`: `volvel dev` previews widgets, with no instance, when the repository defines widgets and no app, or with `--widgets`. `bundle.mjs` builds `dist/widget-host.js` for the published CLI (`files` in package.json); from a checkout the server builds the script with esbuild.
- `dev-widgets-css.ts`: the platform's token values (light and dark) and the page styles.
