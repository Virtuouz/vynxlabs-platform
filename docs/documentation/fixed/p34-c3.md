# Phase 34, lane c3: typing in Page details kept the focus

**Report.** In the documentation editor, each key typed in a Page details field moved the focus to the Markdown editor, so a second character went into the page's text.

**Cause.** Every Page details field writes the page's source through `handle.apply` of the code editor, and the Monaco branch of `apply` always called `created.focus()` (`apps/console/src/editor/CodeEditor.tsx:301`). The plain text box (all unit tests) never focused, so no earlier test could see it.

**Fix.** The shared piece: `apply` takes the focus only when no other text field (input, textarea, select, contenteditable outside the editor) has it (`otherFieldHasFocus`, `CodeEditor.tsx:63`). A toolbar button (Bold, Insert, Heading, the Remove buttons in Page details) is not a text field, so the editor still takes the focus for those.

**Siblings (POLISH-013).** `handle.apply` is called from `DocEditor.change` (the Page details form, the retitle pencil, Discard) and `MarkdownEditor.change` (toolbar and slash insertions); `MarkdownEditor` is the only other user of the code editor's handle. All go through the one `apply`. Undo, redo and reveal still focus: they are asked for from buttons or by a click on a problem.

**Test.** `apps/console/src/editor/CodeEditor.test.tsx`, "a change made from a field beside the editor does not take the focus from the field", seen failing first (focus taken twice). It runs the Monaco path with a stand-in for `monaco.ts` and turns the plain-editor flag off for that test only; the other console tests still never load Monaco.

**Walked** on a throwaway Fernhill instance, real Monaco, at 1440 (light, dark), 768 (dark), 390 (light, dark): typed 17 characters into Title and Description, value whole, focus kept; Tab from Title moved to the next field; saved with Ctrl+S, reloaded, details kept. At 768 and 390 Page details is under the Preview switch of the editor (as before).

**Contract changes:** none. **Left:** nothing.
