# Phase 34, lane c1: a new form trigger opens

Owner's report: "Trying to create form based trigger seems to error." The page showed "Cannot read properties of undefined (reading 'length')".

## Cause

Build, then New trigger, then Form, goes to `/resources/new/trigger?type=form`. `ResourceEditor` made the fresh body as `{ type: "webhook", script: "", ...type: "form" }`, which has no `title` and no `fields`. `FormDesigner` read `trigger.fields.length` (`apps/console/src/screens/FlowSteps.tsx`, `useKeys(trigger.fields.length)`) and threw. Changing the type in the editor's own select did not fail, because it called `newForm()`. Two places made a "fresh trigger of a type", and only one knew what a form starts as.

## Change

- `apps/console/src/screens/ResourceEditor.tsx`: new `freshStart(type)` (webhook, event, form), used by both the `?type=` open and the type select. The form starts as `newForm()` (title "Tell us", one required Message question).

## Test

`ResourceEditor.test.tsx`: "a new trigger asked for as a form opens with a form to fill in, and saves". Seen failing first with the TypeError above at `FlowSteps.tsx:682`; it now passes. (Another test in that file, "a schedule the repository's code defines is moved to a file...", fails with and without this change, and is not from this lane.)

## Siblings looked at (POLISH-013)

The other kinds' `fresh` bodies in `ABOUT` (connector, connection_group, variable, event, schedule, data source) are each drawn by editors that read optional fields. The webhook and event trigger starts draw. Flow trigger nodes already use `newForm()`.

## Walk

Throwaway instance seeded with Fernhill, Sandbox workspace. At 1440, 768 and 390, light and dark: opened `?type=form`, filled the path, the script and the title by keyboard, saved the draft with Enter, reloaded and found the title kept. No page error, no horizontal scroll, in all six.
