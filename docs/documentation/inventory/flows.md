**6 Behavior**
- Several outgoing connections run in parallel. Any step but a Join starts on the **first** path to arrive, once. Join waits for paths that can still arrive (ENG:709-712).
- An unhandled failure cancels everything active and fails the run. Error path taken: step marked `handled`.
- Retries are the **script's** own (default 0); steps have no retry setting.
- State saved per step; the sweep runs every 2 s, up to 200 runs (`ENG:1349-1370`), so waits are accurate to about 2 s. A pass that throws three sweeps in a row fails its run with the reason (`ENG:1394`, FLW-02). A value the database cannot hold is cleaned or refused, naming where.
- Runs and sub-flows are pinned to the starting version.
- Workspace concurrency (default 10, 1-1000) limits script runs only (`kernel/execution/runs.ts:471`); no flow-run cap.
- 200 nodes (`SCH`, `maxProperties`), 1000 edges, no cycles. Payload over 256 KB is kept in storage and shown as `{stored, note}` in expressions; a sub-flow's large answer carries the same note (`flow_run.output_ref`, FLW-33).
- A flow's last steps give its output; a last step with only an error path after it still counts (`ENG` `#finish`, FLW-25).
- One drafts-together deploy applies manifests in kind order, so a schedule at an earlier path than its flow deploys (`deploy.ts`, fix-flowops).
- Platform events: a run that is canceled publishes `platform/run-finished` with status `cancelled` (D50).

## C. Gotchas
- JSON numbers are doubles: `trigger.n + 1` fails, `+ 1.0` works; `trigger.n % 2.0` fails, use `int()`; text + number needs `string()`; comparing with ints works; `7 / 2` is 3 [ran]. Not a fault (FLW-34): write them on the page.
- A missing field is an error, so use `has()`. Unanswered optional form fields are absent.
- Flow output = the last steps only, by name. A last step with only an error path **is** in it now (FLW-25).
- Rejection/timeout text is in `steps.x.error.message`; output is readable only on approval.
- A test runs real scripts and mails approvers "[Test] Approval needed". It builds with the draft tested and the drafts it names, not another person's broken draft (D32); "Build with all drafts" is the old behavior.
- Saving a repository flow's draft takes it over (the editor says so and does not autosave it).
- Branch and Set can fail and now have an error path in the console (FLW-MP10); a Start, Join, Wait and Fail have none.
- "In 24 hours" means the last 24 hours (FLW-28; the list, inspector and tenant overview say it).
- Removing a step does not ask: say Undo is in the message (D34).
- Renaming a webhook or form start in a flow that is already saved keeps its address through the `key`; renaming it in a new flow does not need to.
- A trigger source's tick may start at most 100 items; a step in a flow cannot raise this.
