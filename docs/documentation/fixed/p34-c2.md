# p34-c2: a connection test that gets a 4xx or 5xx is not a success

Report: "Supplier reached messages state 404 but show up as successful." Fernhill's `supplier` test said "Reached (404)" in a success tone.

## Decision
Only a 2xx or 3xx answer is reached. 401/403/407 fail ("refused the credentials, check the secret"), 404/410 fail ("nothing is at that address, check the base URL or set a test path"), 5xx fail ("the service is failing"), other 4xx fail. The stored health has only ok/problem, so no warning state was added: all of these are `ok: false`, with a reason that says the service answered. No migration.

## Changed
- `packages/sdk/src/http.ts`: new optional http config `testPath` (type, schema field "Test path"); `httpConnector.test` asks for it (else the base address) and throws with status and the reason above for any non-2xx/3xx.
- Health follows with no other change: `kernel/execution/connection-health.ts` stores `ok:false` and "HTTP 404: ..." from the worker's result; every view reads that one stored value.
- `examples/fernhill/stand-ins/server.mjs`: `GET /textline/ping`, `GET /vetsupply/ping` (200 with the token). `examples/fernhill/setup/setup.mjs`: `sms` and `supplier` bind `testPath: "/ping"`.
- Docs: `connections.md` (result table), `set-up-a-connection.md` (404 troubleshooting), `call-an-api.md` step 4 (Test path `/vetsupply/ping`). `pnpm docs:check` passes.

## Tests
- `packages/sdk/src/http.test.ts`: "Test fails on a 4xx or 5xx answer, and says what to check".
- `apps/control-plane/src/connections.test.ts`: "an address that answers 404 is not reached, and a test path that answers well is" (task result and stored health).
- `apps/console/src/Connections.test.tsx`: "a test that got a 404 or a refusal is not said as a success" (`testText`). Console already drew `ok:false` as Failed; this pins it. The old SDK test asserted 404 = reached, so it was rewritten with the fix rather than seen failing separately.
