# Phase 34, lane a2: shared ownership and pull first

## What changed
- Basis: `resource.basis_hash` (migration `packages/db/migrations/0101_a2_resource_basis.sql`, locked; the integrator may need to renumber). Hash and helpers: `apps/control-plane/src/kernel/execution/basis.ts` (`contentHash`, `setBasis`, `setBasisTo`, `carryBasis`).
- Refusal: `deployBundle` option `repository: { force }` (`kernel/execution/deploy.ts`, after `leaving`). Set by `POST deployments` (body `force`) and `deployment-preview` (query `force`). Refuses `409 console_changed`, one issue per path, "changed" (replaced, differs from basis) or "made" (would be removed, no basis); `allowDelete` and settled-draft paths exempt removals. A workspace with no basis at all (console-only, or first repository deploy) is never refused. `--force` writes audit `deployment.forced` (paths and kinds of change). After a repository deploy every files resource it carries gets a new basis.
- Pull: `GET resource-files` returns `basis` (path, hash of deployed files resources); new `POST resource-basis` (needs `deployment:write`, audit `resource.basis_set`) stores what a pull took. CLI `pull.ts` sends the resources it did not keep.
- Git sync: push (not push-with-drafts) and pull set the basis (`kernel/git.ts`); a pull leaves out resources whose files still differ from the branch. Promotion carries it (`promote.ts`).
- CLI: `volvel deploy --force`, `--preview` passes it, refusal prints each path (`cli.ts` `problemLine`). The old client check for removals is skipped with `--force`.
- Words: `apps/console/src/kit/ownership.ts` (Files / Code), used by `definedWhere`, Data Tables list column and description, Execution script inspector, ObjectPages.
- Also (coordinator's note from a1): `storeBundle` passes `tenantRoles` (tenant's and built-in roles) to `checkBundleManifests` (`kernel/execution/bundles.ts`).
- New audit actions `deployment.forced`, `resource.basis_set`; error code `console_changed` (`packages/manifest/src/errors.ts`).
