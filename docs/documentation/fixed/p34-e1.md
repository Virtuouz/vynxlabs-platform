# p34-e1: a frame's write events are confirmed on the page

Owner decision 2026-11-24, amending decision 0005.

## What changed

- `packages/widget-sdk/src/action.ts`: `STEP_EFFECT` classifies every step kind as `write` or `moves` (a `Record<StepKind, ...>`, so a new kind does not compile unclassified), and `changesAnything(action)`. Test `packages/widget-sdk/src/action.test.ts` fails when a kind is added without it, and when the writes differ from `SERVER_STEPS`.
- `packages/screens/src/PageView.tsx` (`emit`): a request from a tenant (`x/`) widget carries `gate: {widget, event}`. Core widgets do not.
- `packages/screens/src/actions.tsx` (`useActions.run`, `Confirmation`): a gated request whose action changes anything opens the existing kit-`Dialog` confirmation with words the page makes (`gateWords` in `confirmWords.ts`: "Run the script 'Close open orders' for the client of Northside?", naming widget and event). Cancel is the default focus, Escape cancels, focus returns by the Dialog. While one is open a further gated write is dropped with a `console.warn`, not queued. An action that already has its own confirmation keeps it, and is also subject to the one-at-a-time drop. The frame's rate limits are unchanged.
- `apps/console/src/kit/inspector/actionControls.tsx` (`ActionEditor`, shared by every action editor): for an `x/` widget whose action writes, one sentence says members are asked to confirm.
- e2e fixture: `x/hostile` gains a `wipe` event, an `autoWrite` setting and a "Write a note" button; a `writer` app places it with `wipe` wired to a `create` step.
- Docs: decision 0005 amendment; `how-widgets-are-kept-safe.md`; `widget-data-and-events.md`. `pnpm docs:check` passes.

## Tests (seen failing first)

`packages/screens/src/frame-events.test.tsx` (6: dialog and nothing runs until Confirm; Cancel focused and Cancel runs nothing; Escape; second event dropped and logged; filter event runs at once; core widget unchanged; 4 failed with the gate removed). `apps/console/src/inspector-actions.test.tsx` (sentence shown for a tenant write, not for a filter or a core widget). `e2e/widget-frame.spec.ts`, new last test: the frame raises `wipe` with no click, the dialog shows and no note exists; Escape leaves the data; a real press then Confirm adds exactly one; a reload asks again. Whole spec: 9 passed. Packages/screens and widget-sdk unit tests: 523 passed. tsc -b and -p screens, console clean.

## Contract for other lanes

`Request` (`actions.tsx`) has a new optional `gate`. Anything that runs a tenant widget's event through `run` must pass it.
