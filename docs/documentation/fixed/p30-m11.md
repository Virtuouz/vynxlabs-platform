# Phase 30 M11: static export

## Built

- **`@volvel/docs-site/export`** (`packages/docs-site/src/export.ts`): `exportSite(options)` (async generator of `{file, bytes}`), `exportToDirectory`, `directorySource`, `searchClient`. Writes every page (`<url>/index.html`, trailing slashes) drawn by `docPage` from a `SiteView` (product profile, base path, version, `trailingSlash`, static search), `<url>.md` from the package's `md/`, `404.html`, `_search/index.html`, hashed `_platform/docs.<h>.css|js`, `search.<h>.js`, `theme.<h>.css`, `assets/` (screenshots in light and dark), per-collection `search/<collection>.json` and `search/index.json` (crumbs), stubs (meta refresh, canonical, link) for every moved path, `_redirects`, `sitemap.xml`, `versions.json` (`previous` versions are kept). Refuses a base that is not `/x/` and a date that is not a day; reports a move to a missing page through `warn`.
- **CLI** `packages/docs/export.mjs`, root script `pnpm docs:export --out <dir> --base /docs/ [--origin] [--versions] [--theme] [--diagrams] [--version] [--date] [--title]`. Default theme is the instance's own (`DEFAULT_THEME`, `themeCss`, newly re-exported from `apps/control-plane/src/testing.ts`).
- **Search without a server.** `packages/docs-engine/src/search-query.ts` is the query half of `search.ts` (split; `search.ts` keeps the builder and re-exports; subpath `@volvel/docs-engine/search-query`). `PageHit` gained `score`, so the answers of several indexes are put in order. The client (`SEARCH_CLIENT` in `export.ts`) is bundled by esbuild (new dependency of docs-site, already in the lockfile at 0.28.2) so it never needs the markup half.
- **docs-site changes, all optional** (`render.ts`, `script.ts`, `css.ts`): `SiteView.search.module`; `resolve.screenshotDark`; a static site's search address is `_search/`; `searchPage` for a static site has a results place and a list of all pages; script: `answerOf` (module or server), the `_search/` page reads `?q=`, `to()` gives the address its slash, diagrams from `data.platform` on a static site. A site with a server is drawn and scripted as before; the 17 old goldens did not change.
- **markup**: `RenderOptions.screenshotDark` draws two pictures (`vd-shot-light`, `vd-shot-dark`) and DOC_CSS/DOC_DARK_CSS show one by the page's look (system or `data-theme`).
- **Release**: `.github/workflows/release.yml` exports after the rehearsal, uploads artifact `docs-site`, and the existing website dispatch (kept, only when `DOCS_SITE_REPOSITORY` is set) now also carries `run`, `artifact`, `base`. Repository variables `DOCS_EXPORT_BASE` (default `/docs/`) and `DOCS_URL` (origin for the sitemap). `scripts/release-check.mjs` holds `dist/export.js` and `dist/search-query.js`.
- **Handoff**: `packages/docs-site/EXPORT.md`.

## Left, and why

- The browser check was on a scratch export, not a committed spec; the layout of `_search/` and the screenshot pair in dark were not looked at by eye at 390 px. Walk: `pnpm docs:export --out /tmp/x --base /docs/`, serve it, then `_search/?q=table`, Ctrl+K, a page with `::screenshot` (none in the content until phase 31 adds pictures), light/dark, 1440/768/390.
- Reader's light/dark follows the system; no stored choice (the console's `vx-pref:theme` belongs to its own origin). Feedback is not drawn.
- `canonical` is only on moved-page stubs, not on every page: the site's address is not known to the pages.
- Old versions fetching `../versions.json` to say a newer one exists is the website's page script, not built here.
- No diagram in the content today; `diagrams.js` is copied when the console is built (`--diagrams`), not tested.
- Dark screenshot CSS uses `:has()` (all current browsers); older ones show both pictures.

## Callers of what changed

`search.ts` exports unchanged (`index.ts`). `PageHit.score` is added, `searchAnswer` does not send it. `searchPage`, `docPage`, `homePage`, `notFoundPage` callers: control-plane `front.ts`, `product-docs.ts`, CLI `dev-site.ts`: none passes `search.kind: "static"`, so they draw as before.
