# Phase 34, lane a6: take-over for tables

## What changed
- Server: `PUT resources/*` takes `takeOver` (`apps/control-plane/src/routes/workspaces.ts`, schema and handler). For a table with `ownership: "ui"` it passes `switchOwnership` to `putResource`, the same flag a deploy passes, then sets the pull-first basis (`setBasis`) so a later repository deploy that would replace what the console changed is refused `console_changed`. Production is refused by the existing `refuseDirectProductionWrite` (a code resource is changed by a deploy only); so is DELETE ("Retire table").
- `putResource` (`kernel/resources.ts`) audits `ownershipFrom`/`ownership` on `resource.updated` when ownership changes and returns `ownershipFrom` (shared by deploy).
- Console: `Definition` in `screens/Data.tsx` (notice, `takeOver`, confirmation); words in `kit/ownership.ts` (`takeOverConsequence`, new). Notice: "Take over in the console" (dev, with `resource:write`); in production it says a production workspace changes by a deploy only; without permission the usual `mayDefine.line` shows.

## Deviation to know
Tables have no drafts in this product (every table edit is a live `PUT resources`, which alters the database), so the take-over is a live switch in a dev workspace, not a draft that waits for deploy. Hence no "Takes over from code" line in Release for tables. A drafted take-over would need tables to have drafts first (a larger change): the owner's call.

## Shared piece
`takeOverConsequence` is used only by Data; FlowEditor, Queries, Authoring, ResourceEditor, AppBuilder and Dashboards keep their own sentences and could use it. Authoring's code scripts still say a code script "cannot be turned into one the console edits".
