# Phase 34, lane b4: the sandboxed frame

## What changed
- `packages/screens/src/TenantWidgetHost.tsx`: the body of `TenantWidgetHost` is the host side of the protocol. `<iframe sandbox="allow-scripts" referrerpolicy="no-referrer" allow="" title=<widget title>>`, src `<origin>/_widgets/<tenant slug>/x/<name>@<version>/frame.html`. Loading text, "This widget did not load" after `FRAME_READY_MS` (10 s) with no `ready`, "This widget was stopped: it sent too many messages" (iframe removed, `console.error`). The frame is laid over its cell, so a requested height is `min(asked, 100%)` and at most `MAX_FRAME_HEIGHT`; on a stacked page the cell is as tall as the rows it was placed in. Props are posted (`targetOrigin "*"`, only `{config, data, state, size, theme}`) on `ready` and when any changes. `data-frame-phase`, `data-frame-dropped`, `data-frame-asked` on the section are for tests.
- `packages/screens/src/frameChannel.ts`: what a frame's message may be: `isFrameMessage`, declared event only, payload against the event's JSON Schema (or what `gives` names), 64 KB, 20 per second, flood stop after 2 s over the rate, height clamped. `packages/widget-sdk/src/schema.ts` (`payloadProblem`, exported from `@volvel/widgets/frame`): a JSON Schema walker with no `eval` (Ajv cannot run in an app, whose policy refuses it). The host believes a message only when `event.source` is the iframe's own non-null `contentWindow`.
- `frameSource.ts` (where frames are served from; `setFrameSource`), `frameTheme.ts` (the page's `--vx-*` values and light/dark, re-sent when the scheme changes). The served app sets the source from its own address (`packages/screens/runtime/main.tsx`); the console from `GET /instance` and `GET /tenants/<id>` (`screens/builder/registry.ts`). Every place that draws a page uses `workspaceViews`, so the console canvas, published apps and dashboards all use the one host.
- `apps/control-plane/src/routes/instance.ts`: `GET /instance` also says `appsUrl` (origin or null).
- Policy: `WIDGET_POLICY` now ends `; sandbox allow-scripts`, so the page is opaque even when opened on its own. With that, `front.ts` serves `/_widgets/...` at the console address when the instance has no apps address (it still redirects to the apps address when there is one). Without it, an instance with no `APPS_URL` (the CI instance) could draw no widget.
- `packages/cli/src/widget.ts`: the scaffold's view used `--volvel-foreground` / `--volvel-card`, which the host does not send. The tokens are `--vx-*` names without the prefix: `--volvel-ink`, `--volvel-surface`, `--volvel-action`, and the rest of `THEME_TOKENS`.

## Tests
`packages/screens/src/frameChannel.test.ts` (undeclared, bad payload, oversize, no protocol, flood, size), `tenant-widgets.test.tsx` ("the frame": sandbox attributes, only its own window, props posted and re-posted, size, flood removes it, did not load, no address), `packages/widget-sdk/src/schema.test.ts`, `apps/control-plane/src/widgets.test.ts` (served at the console address with the policy). Written with the code, not before it: a mutation (accept any `source`) was not run.
`e2e/widget-frame.spec.ts` (`@builder @access`) deploys `e2e/widget-frame-fixture` (a hostile widget) with the CLI: fetch of the API (relative and absolute), another origin, XHR, cookie, localStorage, `parent.document`, top and parent navigation, `window.open`, an undeclared event, three malformed payloads (one 70 KB), a bare string, a huge box and a huge height. Each fails, no request to the API is answered, the address does not change, six messages are dropped, a declared event reaches the page, the data is the server's, the frame stays in its cell; the same on a dashboard and in the builder, light and dark, keyboard in and out, reload. Run: `playwright test -c e2e widget-frame --no-deps --project=parallel` on a throwaway instance (the setup project needs Fernhill).

## Contract changes other lanes must know
- `GET /instance` has `appsUrl`. `WIDGET_POLICY` has `sandbox allow-scripts`. Widget files are served at the console address when no apps address is set.
- B5 (`volvel dev`) should use the same policy and the same theme token names.
- B6 docs: scaffold token names are `--volvel-<token>`, tokens in `THEME_TOKENS`.
