# p34-h2: layout measures after the larger type (polish-layout)

Failures: `polish-layout.spec.ts:24` (first row within 160 px: runs 170, a table's rows 165, a data source's rows 165, tenants, instance members, operators 164) and `:83` (text drawn over its neighbour: "When not given" at 768 on the Definition tab, "Who sees rows" at 1280 on Tables, "Actions2" on the kit's drawer at 1280). Real faults of the 16 px scale; the measures are unchanged.

## What changed
- `apps/console/src/kit/DataTable.tsx` (heading row): column headings may wrap (no `whitespace-nowrap`; the table is `table-fixed`, so a nowrap heading overflowed its percentage column), and the heading row is `py-1` (was `py-2`; the line grew with the type, the padding did not scale). All DataTable lists.
- `packages/ui/src/Grid.tsx`: the editable grid's and the read-only grid's heading rows are `py-1` whatever the density (the density padding is for body rows); the filter row's bottom padding is `pb-0.5`. Fixes a table's rows and a data source's rows (165 to under 160).
- `apps/console/src/kit/layout.tsx` `FilterChips`: chips `px-2.5` (was `px-3`). Runs' status chips plus its actions were 25 px wider than the row and wrapped to a second line (first row at 170). Other users: every screen using FilterChips.
- `packages/ui/src/drawer/Drawer.tsx` `DrawerTabs`: tabs are `flex-auto` (own width, then share), no longer `min-w-0 flex-1`, so a label with its count is never narrower than itself. Users: the inspector drawer, the kit drawer.
