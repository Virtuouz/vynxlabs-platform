# p34-c4: the console's type scale

Owner: body 16 px up to 1920 CSS px, 18 px at 2K, 20 px at 4K; headings the same ratio.

## What changed
- `packages/ui/src/type-scale.css` (new, exported as `@volvel/ui/type-scale.css`, copied to dist; also in `scripts/release-check.mjs`), imported by `apps/console/src/styles.css` AND `packages/screens/runtime/styles.css`: `--vx-type-scale` is 16/14, 18/14 (from 2560 px), 20/14 (from 3840 px). Steps, not a ramp: 1921-2559 stays 16, 2561-3839 stays 18.
- `packages/ui/src/tokens.css` (type roles and `body`): every role's size and line height is `calc(Npx * var(--vx-type-scale, 1))`. The roles were written for a 14 px body, so the scale is body/14 and headings follow (display 20 -> 22.9 / 25.7 / 28.6). Fallback 1: an app that imports tokens.css is unchanged.
- Spacing, icons and rem stay put (root font-size not touched, so rem-measuring code in PageView and DataTable is unaffected).
- Followed by hand: `packages/widgets-core/views/{goal,stat,cells,table,detail}.tsx` (arbitrary px sizes now calc with the scale); Monaco `fontSize` in `apps/console/src/editor/CodeEditor.tsx` reads the scale when created.
- Phones: `styles.css` sets text boxes to `max(16px, 1em)` under 640 px.
- Not scaled: FlowGraph SVG text (fixed node boxes), `diagrams/draw.ts`, chart spec font 10, Doc.tsx served docs (own 16 px). The docs site does not load it: unchanged.

## WYSIWYG (coordinator's point 1)
Chosen: give the runtime the same rule, by importing the one shared file. So the builder canvas, app preview and dashboards (portals, sheets and dialogs too, which a wrapper would have missed) draw at the size the published app does at the same viewport. Consequence: served apps also go from a 14 px body to 16/18/20. `enforce.test.ts` pins that both stylesheets import the file. Apps that import only tokens.css stay at scale 1.

## Rail
At 2560+ the rail's labels (Overview, Configure) clipped in a fixed 64 px rail. `--vx-type-growth` (1, 18/16, 20/16) in type-scale.css; `Shell.tsx` rail width, item width and flyout offset multiply by it.

## Test
`apps/console/src/enforce.test.ts`: root rules exist; no `--text-*` in tokens.css is bare px; body uses the scale.

## Looked at
Real browser, 390/768/1440/1920/2560/3840, light and dark, instance screens: body and h1 sizes as above, no horizontal overflow, inputs 16 px at 390. Fernhill seeded (sandbox workspace): tables/appointments (big table), Clinic operations builder, a flow editor (appointments/after-visit), Runs, Deploy, dashboard clinic-visits, at 390/768/1440/2560/3840, light and dark, reload and Tab (focus ring visible): no horizontal overflow and no clipped labels after the rail fix. The flow canvas's nodes keep their size (React Flow zoom, text not scaled), so they fit but look small beside 20 px text at 4K; left as is. Port 4364 was held by lane c3, so port 4374 was used.

## Note
The browser reports CSS pixels: a 4K screen at 150% Windows scaling is 2560 wide and gets 18 px.
