# Phase 34, A1: one source for both forms

## What changed
- `packages/manifest/src/json-schema-ts.ts`: a small JSON Schema to TypeScript converter (objects, arrays, enum, const, oneOf/anyOf, `$ref` within the file, additionalProperties, required; no dependency). Descriptions become doc comments.
- `packages/manifest/src/emit.ts` (`renderKindTypes`, `writeKindTypes`, `staleKindTypes`) and `emit-cli.ts`: `pnpm emit:schemas` also writes `packages/sdk/src/generated/kinds.ts`, one `<Kind>Body` per kind (newest version, from the file schemas); `pnpm check:schemas` covers it. `manifest.test.ts` holds it fresh. `biome.json` ignores `**/generated`.
- `packages/sdk/src/index.ts`: every `*Options` is now the generated body plus the SDK's helpers (`Take<Body, Over, Skip>`): refs by definition, zod, flat `uses`, tuples for edges, `{owner}`/`{rules}` policies. `bodyOf()` passes every other option into the body, so a field added to a kind reaches its manifest. `KindBodies` is exported (`export type * as`).
- Drift the generated types exposed and fixed: `defineSchedule` had no `flow`; `defineWebhook` and `defineEventTrigger` dropped `tags`.
- `packages/worker/src/define-parity.types.ts` (compiled by tsc; per kind, every nested field of the body must be a field of the options, with named excuses) and `define-parity.test.ts` (each define* example validates against its kind's schema; every schema field reaches the manifest). It lives in worker because it is the package that depends on both manifest and sdk.
- Build check: `checkBundleManifests(manifests, { tenantRoles? })` in `bundle-check.ts`; a binding's `role` that is a role's path is refused (names the name); an unknown name is refused when `tenantRoles` is given. `BUILTIN_ROLE_NAMES` (permissions.ts) is held to the database by `apps/control-plane/src/builtin-role-names.test.ts`.
- `packages/cli/src/build.test.ts:382`: a fixture passed `execute` to `defineScript` (ignored before); now `run`.

## What I looked at
No screen changed, so no browser walk. `tsc -b`, the three examples' tsconfigs, `docs:generate` and `docs:check` pass; tests: manifest, sdk, worker parity, cli build and examples, control-plane builtin-role-names.

## Contract for other lanes
- Any new kind or field in `kinds.ts` regenerates `generated/kinds.ts` (run `pnpm emit:schemas`; the stale check fails otherwise). b1: a `widget` kind with a `define*` needs an entry in the parity types and test; one without is listed in the test's "no define*" list.
- An unknown option on a `define*` is now a schema error ("additional properties") instead of ignored.
- `checkBundleManifests` has an optional second argument.
