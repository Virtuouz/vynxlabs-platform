# Phase 30 M9, first part: the generators

Rows: API-01..07, API-13 (links half), API-14, API-23, the audit-area test. Tests were written with the code; the generators had none.

## Built

- `packages/docs/generators/api.mjs`: `apiFiles()` uses `describeApi()` (no Postgres, no app to stop). `apiPages()` gives `api/index.md` and one page per tag (33; `api/<tag>.md`): summary, description, access from `x-access` (custom routes print their own `says`), parameters, request body, responses, one table per union form. Index groups tags: people, programs (worker protocol, worker host, SCIM), sign-in; and lists routes that do not carry JSON (derived from declared content types: API-13 links half is derived, written pages to link to do not exist yet).
- `packages/docs/generate.mjs`: `expected()`, `stale()`, `write()` are async and include the API pages and `openapi.json`; `KEPT` is gone (API-14, API-23). `docs:generate` and `docs:check` call `generate.mjs`. SHARED FILE: `packages/docs/check.mjs` got `await` on `stale()` and `write()` (m4 owns it) and `scripts/docs-check.test.mjs` names `docs/generate.mjs`.
- `packages/docs/generators/schema.mjs`: `tablesOf()` gives one table per union form at any depth, keyed by the discriminator; limits now print defaults, enums, min/max, lengths, items, format, pattern, examples. `fieldsOf` is unchanged (coverage floor and console descriptions read it).
- `packages/docs/generators/reference.mjs`: kinds pages are drawn from `fileSchemas()` (no `entry`/`source`), carry the true file name, the version, the code-file note, the right article, and the index has the file envelope for a workspace and for a tenant.
- `packages/manifest/src/files.ts` `resourceFileName()` and `tenant.ts` `tenantFileName()`: the one place that names a file, used by render, `fileOf`, parse and the generator (API-02).
- `apps/control-plane/src/api-description.ts`: `SIGN_IN_ROUTES` gives every library route a summary and description; routes of a feature the options switch off are dropped from the description. `kernel/auth.ts` `signInFeatures()` reads the options (API-07, API-08 for the library). `app.ts` passes them to `finish()`.
- Route summaries: all of our routes already had one (`app.test.ts` test exists); the 33 missing were the library's.

## Tests

- `apps/control-plane/src/describe-api.test.ts`: every operation, library included, has summary and description (fails for a new route or library route without one); sign-up, social, change-email, delete-user are not listed.
- `packages/docs/src/generators.test.ts`: a field needed by one form is needed only in its table (API-01); file names equal the manifest's (API-02, 04); no `entry`/`source` (API-03); defaults, enums, limits, patterns (API-05); a page per tag and every route on its page, no "Decided by what is asked for" (API-06); sign-in page (API-07); a changed API page or `openapi.json` makes `stale()` report it (API-14, 23).
- `apps/console/src/Audit.test.tsx`: template-first audit actions are listed exactly and their words have areas.
