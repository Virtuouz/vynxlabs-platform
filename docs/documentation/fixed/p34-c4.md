# p34-c4: the console's type scale

Owner: body 16 px up to 1920 CSS px, 18 px at 2K, 20 px at 4K; headings the same ratio.

## What changed
- `apps/console/src/styles.css` (`:root` and two `@media (min-width)` rules): `--vx-type-scale` is 16/14, 18/14 (from 2560 px), 20/14 (from 3840 px). Steps, not a ramp: 1921-2559 stays 16, 2561-3839 stays 18.
- `packages/ui/src/tokens.css` (type roles and `body`): every role's size and line height is `calc(Npx * var(--vx-type-scale, 1))`. The roles were written for a 14 px body, so the scale is body/14 and headings follow (display 20 -> 22.9 / 25.7 / 28.6). Fallback 1: an app that imports tokens.css is unchanged.
- Spacing, icons and rem stay put (root font-size not touched, so rem-measuring code in PageView and DataTable is unaffected).
- Followed by hand: `packages/widgets-core/views/{goal,stat,cells,table,detail}.tsx` (arbitrary px sizes now calc with the scale); Monaco `fontSize` in `apps/console/src/editor/CodeEditor.tsx` reads the scale when created.
- Phones: `styles.css` sets text boxes to `max(16px, 1em)` under 640 px.
- Not scaled: FlowGraph SVG text (fixed node boxes), `diagrams/draw.ts`, chart spec font 10, Doc.tsx served docs (own 16 px). Published apps runtime, docs site and `screens/runtime/styles.css` do not load the console stylesheet: unchanged.

## Test
`apps/console/src/enforce.test.ts`: root rules exist; no `--text-*` in tokens.css is bare px; body uses the scale.

## Looked at
Real browser, 390/768/1440/1920/2560/3840, light and dark, instance screens: body and h1 sizes as above, no horizontal overflow, inputs 16 px at 390. Not walked: Fernhill dense screens (tables, builder, flow editor), not seeded; keyboard only spot-checked. Port 4364 was held by lane c3, so port 4374 was used.

## Note
The browser reports CSS pixels: a 4K screen at 150% Windows scaling is 2560 wide and gets 18 px.
