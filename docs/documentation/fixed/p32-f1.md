# p32-f1: Fernhill specs on several workers

Before: the `fernhill` project ran on one worker, one seeded tenant, about 8.7 min.

## What changed

- `examples/fernhill/setup/setup.mjs`: `FERNHILL_SLUG` (default `fernhill`) names the tenant. People are
  instance-wide: `POST /tenants/:t/members` adds the existing member with an email and ignores the
  password, so a copy adds Maya, Rowan, Devi, Amara, the locums and Sam as they are. Two copies seeded at
  once may both try to create a new account; `addMember` asks again, and finds it. A copy's portal
  hostname is `<slug>.localhost`, its tenant name says which copy, and it writes no `demo.json`. End
  users and groups are per tenant and clash with nothing. The existing-tenant check now searches by slug
  (the instance's list is paged, and 200 tenants fill the first page).
- `e2e/fernhill.ts`: a worker claims a copy (`fernhill-w0`...) on first use, by a claim file holding its
  pid (a dead holder is taken over). `E2E_FERNHILL_COPIES` (default 3) says how many;
  `E2E_FERNHILL_TENANT` still pins one tenant.
- `e2e/fernhill-copies.setup.ts` (project `fernhill-copies`, dependency of `fernhill` only): seeds the
  missing copies in parallel, shares the stand-ins, and signs Jess in at each copy's portal
  (`.auth/jess-<copy>.json`; a portal cookie is per tenant, console sessions are the person's own).
- Specs read `fernhillTenant()`; hard-coded `/apps/fernhill/`, `/portal/fernhill/` and `slug === "fernhill"`
  in phase-25, 28, 28-approvals, 28-group-rows, 28-canvas now use the worker's. Tenant lookups search
  by slug. `screenshots` keeps the original `fernhill`, which no copy touches.
- `playwright.config.ts`: `fernhill` has `workers: E2E_FERNHILL_COPIES`.

## Result

First run on the e2e instance (3 copies seeded in 50 s): 138 passed, 2 skipped, 1 failed (phase-25
publish button disabled; passed on its rerun) in 5.2 min. Second run, copies reused: 139 passed, 2 skipped, 4.3 min.
