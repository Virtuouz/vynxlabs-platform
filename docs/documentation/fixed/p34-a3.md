# Phase 34, lane a3: types generated from the definitions

## What changed

- **The generator** (`packages/manifest/src/env-types.ts`, exported from `index.ts`): `envDeclarations(manifests)` writes a declaration file that augments `@volvel/sdk` (`declare module "@volvel/sdk"`, no value imports). `tableTypes` and `columnValueType` give a table's `row` and `insert` by the rules of `RowOf`/`InsertOf`; `typeOfSchema` turns a JSON Schema into a TypeScript type (const, enum, oneOf/anyOf/allOf, objects, arrays, nullable; anything else `unknown`). Interfaces filled: `VolvelTables`, `VolvelEvents`, `VolvelVariables`, `VolvelConnections`, `VolvelFlows` (manual trigger input), `VolvelScripts` (input/output). `ENV_TYPES_FILE = ".platform/volvel-env.d.ts"`.
- **The SDK** (`packages/sdk/src/context.ts`): the six empty interfaces (exported from `index.ts`, line 18 block). `ctx.table(name)` has an overload typed by a name the interface has; `ctx.events.publish` checks the payload for a known event and a fallback excludes known names (so a wrong payload for a known event is an error); `variable` and `connection` complete known names (`KnownOr`). Unknown names stay untyped; the `defineTable` phantom overload is unchanged. `testing.ts:179,212` and `worker/src/context.ts:261` got explicit parameter types (overloads stop contextual typing).
- **The CLI:** `packages/cli/src/types.ts` (`writeEnvTypes`, skips an unchanged file). `volvel build` and the new `volvel types` write it (`cli.ts`); `volvel dev` writes it at start and `dev-site.ts` on each rebuild. `commands.ts` lists `types`. `local.ts` (`volvel init`): tsconfig `include` is `["src", ".platform/*.d.ts"]`.
- **The control plane:** `GET /tenants/:t/workspaces/:w/types.d.ts` (`routes/execution.ts`, permission `script:read`), from `namedResources` (`kernel/authoring.ts`): the active bundle, code and console, with saved drafts laid over by key.
- **The console:** `CodeEditor` takes `declarations`; `monaco.ts` `setEnvTypes` loads them with `addExtraLib` (replacing the last); `Authoring.tsx` fetches `types.d.ts` through the new `api.text` (a failure is silent; not fetched when the plain editor is in use, so unit tests never load Monaco).

## Tests

- `packages/cli/src/types.test.ts`: a fixture repository (YAML tables, a variable and an event; TS table, variable, event, connection) whose scripts compile with `tsc` against the generated file; eight deliberate faults fail to compile (wrong column, wrong type, unlisted enum value, missing required, unknown column read, code table, event payload shape and extra property); without the file the same script does not compile; a `defineTable` export keeps its types; parity with `RowOf`/`InsertOf` by mutual assignability; script/flow/variable/connection output; the `types` and `build` commands write the file; an unchanged file is not rewritten.
- `apps/control-plane/src/types-route.test.ts`: empty workspace; deployed code resources plus a draft; a deleting draft removes a name; 403 without `script:read`.
- `cli.test.ts` init test follows the new `include`.

## Contract changes for other lanes

- New route `GET …/types.d.ts` (text/plain). `ScriptContext` gained overloads: code that implements `ScriptContext` by hand needs explicit parameter types on `table` and `events.publish`.
- `ENV_TYPES_FILE` and `envDeclarations` are the API for any lane that writes the file (a4 convert, a5 init). `volvel init` must keep `.platform/*.d.ts` in `include`.
- a1: `index.ts` only changed at the `export type { … } from "./context.js"` block.
