# Phase 30, M10: screenshots (DOC-17)

## Built
- `packages/docs/screenshots.mjs`: the manifest of shots (name, address, who is signed in, setup, themes light+dark, viewport, ready, steps, mask), `CLOCK`, `fileName` (name.theme.<12 hex of sha256>.png), `readIndex`/`writeIndex` (`assets/screenshots/index.json`, name -> theme -> file), `missing`. Types in `screenshots.d.mts`.
- `e2e/screenshots.spec.ts`: builds the handbook scene once, then takes every shot in a light and a dark context with `clock.setFixedTime(CLOCK)`; masks `time`, `[data-volatile]` (the connection state, which the fixed clock leaves at "Connecting") and server-written dates; writes hashed files and the index; fails when any shot x theme is missing. Run by `pnpm docs:screenshots` (instance on E2E_URL).
- `packages/docs/build.mjs`: ships only files named in the index; the manifest gets `screenshots` (names, as before) and `screenshotFiles` (`packages/docs-engine/src/output.ts`).
- `apps/console/src/help/HelpPanel.tsx` resolver: name -> file of the console's current look (`useLook` in `apps/console/src/theme.ts`), light as fallback; no `screenshotFiles` (older docs build) gives words.
- `packages/docs/check.mjs`: a `::screenshot{name}` not in the manifest fails `pnpm docs:check` (screenshot rule only).
- `.github/workflows/release.yml`: new `screenshots` job (image, stack, Fernhill seed, `pnpm docs:screenshots`, artifact `docs-screenshots`, 30 days); the release job `needs` it and downloads the artifact before `pnpm build`. Generate and check were already there. Pictures stay gitignored.
