# Phase 34, lane b3: tenant widgets in the builder, the runtime and the checker

## What changed
- One registry per workspace. `packages/widget-sdk/src/index.ts`: `WidgetRegistry.withDeployed(deployed)` (a new registry: the platform's packs plus a workspace's `x/` widgets, every version kept; the one it is made from is left alone), `get(type, version?)`, `versionsOf(type)`, `list()` leaves out a widget the repository no longer defines (`current: null`), `compareVersions`, `updateNotes`, and the shared types `DeployedWidget`, `DeployedWidgetVersion`, `WorkspaceWidgets` (`{items}`), which match b2's `GET .../widgets` (`current` null once removed).
- Checker: `packages/manifest/src/page.ts` `workspaceRegistry(deployed)`; `checkWidgets` uses `registry.get(type, version)` and refuses an `x/` type that is not deployed, a missing version and a version not deployed; `newWidget` records the version for an `x/` widget. `bundle-check.ts` `bundleRegistry`: a page in a bundle may place an `x/` widget the bundle carries; the versions are the control plane's to check (a bundle may place an older one the workspace still has), so an unknown `x/` type is not refused there either.
- Server: `apps/control-plane/src/kernel/widgets.ts` `deployedWidgets`, `workspaceWidgets`, `widgetsUsed` (from b2's `widget_version`). Used by `kernel/pages.ts` (drafts; b2's `versionProblems` keeps the version sentences, the checker's `/version` issues are dropped there), `routes/dashboards.ts` (member dashboards), `kernel/data/query/inputs.ts` `readWidget` (an `x/` widget's data inputs go through the widget-data route like a core widget's, under the viewer's rules) and `kernel/pages/act.ts` `findAction`. The served interface (`routes/interfaces.ts`) now carries `widgets`: the tenant widgets its pages use.
- Served app: `packages/screens/src/TenantWidgetHost.tsx` (new): `TenantWidgetHost` (props: `WidgetViewProps` plus `type`, `version`, `definition`) is the placeholder b4 fills with the sandboxed frame: a box "Widget <title> v<version>" filling its cell. `workspaceViews(platformViews, deployed)` adds a host per widget; `ViewEntry.versions` holds each version's definition; `PageView.tsx` draws and sizes a placed widget by its version and passes `version` to the view (`WidgetViewProps.version`). `packages/screens/runtime/main.tsx` builds its registry from `view.widgets`.
- Console: `apps/console/src/screens/builder/registry.ts` is now a per-workspace store (`setWorkspaceWidgets`, `useWorkspaceWidgets(root)`, `useViews`, `useRegistry`, `definitionOf(type, version?)`, `offeredOn`, `updateOf`, `updated`); `PageEditor`, `AppPreview`, `SheetPreviewHost`, `DashboardView` load it. `AddToPage` lists tenant widgets in their category ("Your widget" under the title). `kit/inspector/Inspector.tsx`: a notice "Version N is deployed. This page uses M." with what changes ("Adds Loud. Removes old.") and a button "Update to vN"; nothing is written until it is pressed; the drawer is drawn from the version the page names; the pack is "Your widgets" (`model.ts` `packName`, `packTitle`).

## Tests (each seen failing first)
`widget-sdk/src/index.test.ts` (registry), `manifest/src/page.test.ts` and `widget.test.ts` (version checks, bundle), `control-plane/src/tenant-widgets.test.ts` (an x/ widget's rows read as two groups of end users and staff, with the policy; listing; refused pages), `screens/src/tenant-widgets.test.tsx` (host, versions), `console/src/tenant-widgets.test.tsx` (Add to page, inspector from an `x/` definition, update only when pressed).

## Contract changes
- `GET .../widgets` shape is b2's (`items`); `@volvel/widgets` types match it.
- `PageWidget.version` is b2's; the builder sets it on add (`newWidget`).
- b4: replace the body of `TenantWidgetHost` (one component); it gets `type`, `version`, `definition`, `config`, `data`, `size`, `emit`.
- `registerWidgets`/`resetWidgets` (the global registry) are no longer used by the server; b2's `widgets.test.ts` still calls them and could drop them.
