# Predictive UX audit

Status: audit only. Nothing in the application was changed. Written 2026-11-20 against `phase-21-docs-redesign` at `f54d4bc`.

The rules in [polish-prevention-rules.md](polish-prevention-rules.md) predict where the console's history of corrections will repeat itself. This audit applied them to the whole of the current application: the console, the served docs site, no-code and code apps, and the kit. Areas that the history never touched were included on purpose. Findings that map to a rule are **historically predicted**. Those that do not are **general review** (Nielsen, WCAG 2.2 AA, visual hierarchy).

## How it was done

- **Inventory.** The console's navigation (`apps/console/src/nav.ts`) was the base:
  - 23 workspace sections in four areas (Build, Operate, Data, Configure);
  - 13 tenant sections in four groups;
  - 9 instance screens;
  - the editors, object pages and sheets under them;
  - the served surfaces: the docs site (`apps/control-plane/src/kernel/apps/docs.ts`, `packages/markup/src/enhance.ts`), no-code apps (`packages/screens`), code apps (`packages/app`) and the kit (`packages/ui`).
  - `docs/uiux/01-current-product-ui-map.md` (149 surfaces at `e737382`) was the older map. Dashboards, queries, access releases and documentation have been added since.
- **Static pass.** The surfaces were read in three areas: build and operate; data, insight and configure; shell, administration and documentation. Each area was read against every rule's detection strategy. Every finding cites code at `path:line`.
  - Before a finding was reported, `docs/phases/*.md` was searched for a deliberate decision. Two were dropped that way: parameter types for unsaved queries (`phase-18-data-insight.md:310`), and undo leaving out a dashboard's name and sharing (`Dashboards.tsx:175`).
- **Runtime pass.** A throwaway instance was built from this commit in its own git worktree, with its own Postgres and object store (separate containers on other ports). It was seeded with `examples/fernhill` (six weeks of history, a TextLine outage, four waiting approvals, an unverified hostname, a docs site). The owner's own running instance and the Fly test instance were not touched.
  - It was driven with Playwright, signed in as Fernhill's people: the owner (tenant admin), the clinical director (viewer) and the contract developer.
  - Every console section listed above was visited at 1440×900 in light and 390×844 in dark. On each, the walk measured overflow, nested scrollers, controls off the edge, `h1` count and truncated text, and tried F1, Escape and reload.
  - Findings were then checked one by one, in the browser or by replaying the console's own requests. Writes went only to Fernhill's `sandbox` (dev) workspace on the throwaway instance.

### Evidence labels

- **Confirmed:** seen at runtime in the browser, or by replaying the console's request against the instance.
- **Probable:** the code path is unambiguous, but it was not run.
- **Speculative:** depends on timing or data that was not traced.
- **Refuted:** predicted from code, and the runtime showed otherwise.

## What the runtime pass found

### The broad walk

- **Overflow and scrolling.** At 1440×900 and 390×844, none of the 37 console screens scrolls sideways, has controls off its edge, or nests a scroller inside a scroller. Phases 16, 18 and 19 hold here.
- **Help and reload.**
  - F1 opens help on every screen.
  - Escape closes it on 36 of 37. On the workspace overview the walk's Escape did not close it. That was not looked into further, so it is not reported.
  - Reload keeps the address on all of them.
- **Two things measured wrong** and were then confirmed (R-01, R-02 below).

## Limits

- Only the findings in the results table were run. The rest are static and labelled so.
- The runtime pass had one tenant's data. Lists past 200 (A3-20), slow networks (A2-19, A3-10) and a member who holds `approval:read` without being an approver were reasoned about, not produced. The viewer and developer in A1-13 stood in for the last.
- No screen reader was used. Accessibility findings are from code and from the walk's measures.
- The served docs site was read, not walked. The phase-21 browser walk (`e2e/documentation.spec.ts`) has still not been run.
