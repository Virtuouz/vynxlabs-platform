# Lane s2 (phase 32, M3): polish-measures, polish-layout and polish-behaviour in parallel

## What changed

- `e2e/polish-setup.ts`: `test` is `./test.ts`'s `test` plus a worker-scoped fixture `polish`. Each worker builds one tenant (`polish-<stamp>-w<workerIndex>`) and deletes it when the worker ends. Teardown no longer deletes the operator's `operator.strip` preference: that preference holds the id of the hidden grant, and a grant belongs to the worker's own tenant, so workers never share it.
- Setup now also waits for the `stock/check` run to finish (a run still queued draws the queue on the Workers screen, which showed up as a false overdraw on a loaded machine) and waits up to 200 s for each run instead of 90 s.
- `SCREEN_GROUPS`, `screensOf`, `workbenchesOf`, `groupLabel`: a static list of screen names (from `screens()` with placeholder ids), cut into groups of 15 (4 groups of 59 screens). A test is declared per group and looks its addresses up from the worker's tenant. `screens()` and `workbenches()` keep their text, so `enforce.test.ts` (which reads that source) passes unchanged (20 tests).
- `polish-measures.spec.ts`: 21 tests (first-row tops; overdraws per group x 4 widths; nested per group), `mode: "parallel"`. Each writes `<outputDir>/polish/parts/<name>.json` and merges all parts, under a lock, into `<outputDir>/polish/polish.json` (same shape as before: firstRowTop, overdraws, nested, notMeasured). Nothing else read the old `polish.json`. The first-row tops are read as a returning member sees them (screen opened twice, a null looked at again), so the number does not depend on which test opened the screen first.
- `polish-layout.spec.ts`: 8 serial tests became 33 parallel ones: overdraws per group x width, nested per group, scroller per width, row actions per width. No screen or width was dropped. The first-row test looks at an over workbench up to three times.
- `polish-behaviour.spec.ts`: still serial in its file, on the worker's tenant. The two "first visit" checks (`seen:audit-log`, `seen:flows`) retry the clear-and-open, because tests on other workers share the operator's seen marks.

## Timings (shared machine, load average 30 to 40 from other lanes)

- Before (workers 1): polish-measures 6.3 min, polish-layout 7.3 min, polish-behaviour 0.4 min.
- After, `--workers=4`: 4.6 and 4.7 min for all three specs together on a quieter machine, 15.9 min once at load 36 to 41. `--workers=6`: 3.2 and 6.8 min. Times vary with the other lanes' load; the work is about 14 min of tests spread over the workers.
- The merged `polish.json` matched the pre-change one (same 16 workbenches, no overdraws, no nested boxes) in 4 of 5 runs; the other differed in the first-row top of `runs` (130 vs 170, a first-visit description), which led to the two-visit rule above.
